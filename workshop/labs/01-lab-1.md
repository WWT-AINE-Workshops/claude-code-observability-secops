# Lab 1: Who is the agent acting as?

**SDLC phase:** Secure & Release · **Stage:** Agent Augmented · **Time:** 40 minutes

## Why this matters

When something goes wrong, the first question is who did it. A coding agent runs commands with the developer's own credentials, so the answer lives in its telemetry or nowhere. In this lab you turn Claude Code's telemetry on, find your own actions in Loki, and see which identity they carry. Then you break the identity on purpose, with an API key, and fix it.

## Before you start

This lab needs nothing beyond the workshop repository, and the tools from the pre-work. There is no app to start and no branch to reset.

- Open a terminal in your `my-claude-code-observability-secops` folder. Every command in this lab runs there.
- Docker is running. On macOS and Windows, that means Docker Desktop is open.
- Have your Anthropic API key ready for step 5. You type it at the terminal. You never paste it into a file, a prompt or the chat.
- If `ANTHROPIC_API_KEY` is already set in your shell, run `unset ANTHROPIC_API_KEY` first, so step 3 uses your Claude account.

## Steps

### Step 1: Start the LGTM stack

**Do this.** Start the container that holds the Collector, Loki, Tempo, Prometheus and Grafana.

```bash
./scripts/run-lgtm.sh
```

What this does: starts one container called `workshop-lgtm` from the `grafana/otel-lgtm:0.37.0` image, on ports 3000, 4317 and 4318, and waits until it is ready. It changes no files.

Then open Grafana in your browser at http://localhost:3000. It needs no sign-in.

**What you should see.** The script ends with `LGTM is ready. Grafana: http://localhost:3000`, and the Grafana home page opens in your browser.

**Why.** You need somewhere for the events to land before you turn them on.

### Step 2: Turn on Claude Code's telemetry

**Do this.** Set the telemetry variables in this terminal.

```bash
source lgtm/claude-otel.env.sh
```

What this does: sets the `CLAUDE_CODE_ENABLE_TELEMETRY` and `OTEL_*` variables in this terminal only. They send events, metrics and traces to `localhost:4318`, with tool details on. It changes no files.

Open `lgtm/claude-otel.env.sh` in your editor and read it. Each line has a comment that says what it does.

In the Code tab of the Claude desktop app: put the same variables in the `env` block of `~/.claude/settings.json`, then start a new session. Remove them after the workshop. Steps 5 and 6 need the CLI, because they set variables in a terminal.

**What you should see.** `Claude Code telemetry is on for this terminal, sending to http://localhost:4318.`

**Why.** Telemetry is off by default. `OTEL_LOG_TOOL_DETAILS=1` adds the commands and file paths, which an investigation needs.

### Step 3: Make Claude Code do something

**Do this.** Start Claude Code in the same terminal. It signs in with your Claude account. No Claude account, or short of time? Skip steps 3 and 4 and go straight to step 5: your events will look like the ones in step 5.

```bash
claude
```

What this does: starts an interactive Claude Code session in this folder. It changes no files.

Paste this into the Claude Code prompt box and press Enter:

```prompt
Read README.md and tell me in one sentence what this repository is for. Then run git log --oneline -1 and tell me what the latest commit says.
```

If Claude Code asks whether it may run the `git log` command, choose **Yes**. Then quit Claude Code: press `Ctrl+D` twice on an empty prompt.

**What you should see.** One sentence about the repository and one about the latest commit. Claude's wording differs from run to run.

**Why.** One file read and one shell command give you two `tool_result` events to look at.

### Step 4: Find your own events in Loki

**Do this.** In Grafana, open **Explore**, choose the **Loki** data source, and switch the query editor from **Builder** to **Code**. Set the time range to **Last 15 minutes**. Paste this query into the query box and press **Run query**:

```logql
{service_name="claude-code"} | event_name="tool_result"
```

Click one of the log lines to open its fields.

**What you should see.** At least two lines that read `claude_code.tool_result`. Each one's fields include `tool_name` (`Read` or `Bash`), `user_email` with your email, `organization_id`, `session_id` and `prompt_id`. The `Bash` one's `tool_parameters` holds the exact `git log` command. If nothing shows yet, wait ten seconds and run the query again.

**Why.** Signed in with a Claude account, every action carries a person, an organization and a session. Loki turns the dots in attribute names into underscores, so `user.email` is `user_email`.

### Step 5: Break the identity with an API key

**Do this.** Run the command below, then paste your API key and press Enter. The terminal shows nothing while you type, so the key never lands on screen or in your shell history.

```bash
read -rs ANTHROPIC_API_KEY
```

What this does: waits for you to paste or type your key and press Enter. Nothing shows as you type. It stores the key in a shell variable in this terminal only, and writes nothing to disk or to your shell history.

Make the variable visible to the programs you start from this terminal.

```bash
export ANTHROPIC_API_KEY
```

What this does: passes `ANTHROPIC_API_KEY` to programs started from this terminal, such as Claude Code. It changes no files.

Start Claude Code again.

```bash
claude
```

What this does: starts Claude Code in this folder. Because `ANTHROPIC_API_KEY` is set, it asks whether to use the key.

When Claude Code asks whether to use the API key, choose **Yes**. Run `/status` and read which credential is active, then press `Esc` to close it. Paste the same prompt as in step 3 into the prompt box and press Enter:

```prompt
Read README.md and tell me in one sentence what this repository is for. Then run git log --oneline -1 and tell me what the latest commit says.
```

Quit with `Ctrl+D` twice on an empty prompt. Then paste this query into Grafana and press **Run query**:

```logql
{service_name="claude-code"} | event_name="tool_result" | user_email=""
```

**What you should see.** `/status` shows the API key as the active credential. The query returns the new events only: they have `user_id` and `session_id`, but no `user_email` and no `organization_id`.

**Why.** With an API key there is no Claude account in the session. `user_id` is a random install ID, not a person, and deleting `~/.claude.json` resets it. This is where investigations stall.

### Step 6: Close the identity gap

**Do this.** Stamp your identity on every event. Put your own work email in place of `you@example.com`.

```bash
export OTEL_RESOURCE_ATTRIBUTES="enduser.id=you@example.com,team.id=secops"
```

What this does: adds `enduser.id` and `team.id` to everything Claude Code exports from this terminal. It changes no files.

Start Claude Code again. It uses your API key, as in step 5.

```bash
claude
```

What this does: starts Claude Code in this folder, with the new attributes.

Paste the same prompt into the prompt box and press Enter:

```prompt
Read README.md and tell me in one sentence what this repository is for. Then run git log --oneline -1 and tell me what the latest commit says.
```

Quit with `Ctrl+D` twice on an empty prompt. Then paste this query into Grafana and press **Run query**:

```logql
{service_name="claude-code"} | event_name="tool_result" | enduser_id!=""
```

**What you should see.** The newest events carry `enduser_id` with the email you typed and `team_id` with `secops`, still with no `user_email`.

**Why.** In production you set `enduser.id` per user through managed settings or a launch wrapper, so a developer can't change it.

### Step 7: Go back to your Claude account

**Do this.** Remove the key and the attributes from this terminal.

```bash
unset ANTHROPIC_API_KEY OTEL_RESOURCE_ATTRIBUTES
```

What this does: removes both variables from this terminal, so Claude Code uses your Claude account again. It changes no files, and the LGTM container keeps running for Lab 2.

**What you should see.** No output. The next `claude` you start uses your Claude account, with no question about an API key.

**Why.** Your key should live in a terminal only for as long as you need it.

## You're done when

The `enduser_id!=""` query in step 6 returns an event with your email in `enduser_id`. Post that value in the chat. On your own, write it in your workbook.

## If it goes wrong

- **`Docker is installed but not running`:** start Docker Desktop, wait until it says it is running, then run step 1 again.
- **`Port 3000 is already in use`:** something else uses the port. The script shows how to find it. Stop that program, or ask the facilitator if there is one.
- **No events in Loki:** check that you ran `source lgtm/claude-otel.env.sh` in the same terminal where you started `claude`. Then set the time range to **Last 1 hour** and run the query again.
- **The `Bash` event has no `tool_parameters`:** `OTEL_LOG_TOOL_DETAILS` is not set. Run step 2 again in this terminal.
- **Claude Code never asks about the API key:** the variable is not exported. Run the `export ANTHROPIC_API_KEY` block again, then start `claude`.
- **You pasted your key somewhere visible:** revoke it in the Claude Console and create a new one.

## Stretch goals

- Make a folder `.claude` with a `settings.json` that sets `OTEL_EXPORTER_OTLP_ENDPOINT` to another address in its `env` block. Start `claude` and send a prompt. Your events still arrive in Loki: Claude Code ignores the exporter variables in a repository's settings, so a cloned repository can't redirect your telemetry. Delete the folder when you are done.
- Read `lgtm/claude-otel.env.sh` as a managed settings file. Which of its lines would you lock, and why? The file lives at `/Library/Application Support/ClaudeCode/managed-settings.json` on macOS and `/etc/claude-code/managed-settings.json` on Linux and WSL.
- Add `OTEL_LOG_USER_PROMPTS=1`, send a prompt, and find the `user_prompt` event. What would your privacy team say about storing it?

## Recap

You sent Claude Code's events to Loki and read the identity on each one. You saw it disappear with an API key, and you put it back with `enduser.id`. In Lab 2 you use the same stack to detect and investigate.
