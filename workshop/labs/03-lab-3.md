# Lab 3: agentgateway as the control point

**SDLC phase:** Secure & Release · **Stage:** Agent Augmented · **Time:** 40 minutes

## Why this matters

Claude Code's telemetry comes from the laptop, and an unmanaged laptop can switch it off. A gateway sees every model request from the network side, whatever the laptop does. In this lab you put agentgateway in front of Claude Code: it rejects requests without a valid key, stamps a user on every request, keeps the real provider key to itself, and cuts a user off in under a minute.

## Before you start

This lab needs nothing beyond the workshop repository, the LGTM container from Lab 1, and agentgateway v1.6.0 from the pre-work.

- This lab needs the CLI, in two terminals, because the gateway settings live in a terminal. If you normally use the desktop app's Code tab, use the CLI for this lab.
- You use **two terminals**, both in your `my-claude-code-observability-secops` folder. Terminal A runs the gateway. Terminal B runs everything else.
- The LGTM container from Lab 1 is still running. Run `./scripts/run-lgtm.sh` if you are not sure: it tells you if the container is already up.
- Have your Anthropic API key ready. Only terminal A ever holds it.
- Open `agentgateway/config.yaml` in your editor and read it. The `sk-agw-...` keys in it are made-up local keys for this lab, not secrets.

## Steps

### Step 1: Start the gateway with the real key (terminal A)

**Do this.** In terminal A, run the command below, then paste your API key and press Enter. The terminal shows nothing while you type.

```bash
read -rs ANTHROPIC_API_KEY
```

What this does: waits for you to paste or type your key and press Enter. Nothing shows as you type. It stores the key in a shell variable in this terminal only, and writes nothing to disk or to your shell history.

Make the key visible to the gateway you start next.

```bash
export ANTHROPIC_API_KEY
```

What this does: passes `ANTHROPIC_API_KEY` to programs started from this terminal. It changes no files.

Start agentgateway with the lab config, and leave it running.

```bash
agentgateway -f agentgateway/config.yaml
```

What this does: starts agentgateway in this terminal with strict API key authentication, two virtual keys, and OTLP export to the LGTM container. It reads the real key from `ANTHROPIC_API_KEY`. It changes no files.

Open the agentgateway UI in your browser at http://localhost:15000. Don't share your screen while the config view is open: check first whether it shows the backend key.

**What you should see.** agentgateway prints its startup log and keeps running. The UI shows the config you loaded.

**Why.** The real key lives only in the gateway's process. Every laptop gets a virtual key that you can revoke.

### Step 2: Knock without a key (terminal B)

**Do this.** In terminal B, send a request with no key at all.

```bash
./scripts/probe-gateway.sh
```

What this does: sends one tiny Messages API request to `http://localhost:4000` with no key, and prints the HTTP status. It changes no files.

Now send one with a key the gateway doesn't know.

```bash
./scripts/probe-gateway.sh sk-agw-wrong
```

What this does: sends the same request with the key `sk-agw-wrong`. It changes no files.

**What you should see.** Both print `HTTP 401: rejected at the gateway.` If either says `rejected by Anthropic`, the gateway let the request through: check `mode: strict` in the config.

**Why.** In strict mode, a request without a valid key never reaches Anthropic.

### Step 3: Run Claude Code through the gateway as Alice (terminal B)

**Do this.** Point Claude Code at the gateway, with Alice's key and telemetry on.

```bash
source agentgateway/claude-agentgateway.env.sh
```

What this does: turns telemetry on, removes `ANTHROPIC_API_KEY` from this terminal, sets `ANTHROPIC_BASE_URL` to the gateway and `ANTHROPIC_AUTH_TOKEN` to Alice's key, and sets `enduser.id` to `alice@example.com`. It changes no files.

Start Claude Code.

```bash
claude
```

What this does: starts Claude Code in this folder. Every model request goes through the gateway.

Paste this into the Claude Code prompt box and press Enter:

```prompt
List the folders in this repository and say in one line what each one is for.
```

Quit with `Ctrl+D` twice on an empty prompt.

**What you should see.** A short list of folders, such as `lgtm`, `secops` and `agentgateway`. In terminal A, agentgateway logs the requests.

**Why.** Claude Code works unchanged behind the gateway. It only needs a base URL and a token.

### Step 4: See one user in both streams

**Do this.** In Grafana, open **Explore**, choose **Loki**, switch to **Code**, and set the time range to **Last 15 minutes**. Paste this query into the query box and press **Run query**:

```logql
{service_name=~"claude-code|agentgateway"} | user_email="alice@example.com" or enduser_id="alice@example.com"
```

Open one line from each service.

**What you should see.** Lines from both services. The `agentgateway` lines are access logs with `user_email` set to `alice@example.com` and the model name. The `claude-code` lines are Claude Code's own events with `enduser_id` set to `alice@example.com`.

**Why.** Two independent views of the same work, joined on the user. Gateway traffic with no client events is a coverage gap. Client events with no gateway traffic are a bypass.

### Step 5: Put the two traces side by side

**Do this.** In **Explore**, choose **Tempo**, then the **Search** tab. Set **Service Name** to `agentgateway` and press **Run query**. Open the newest trace. Then set **Service Name** to `claude-code`, press **Run query**, and open the newest trace there too.

**What you should see.** A gateway span for each model request, with `user.email` and the model in its attributes. Next to it, Claude Code's `claude_code.interaction` trace with its `claude_code.llm_request` spans.

**Why.** The gateway span is what the network saw. The Claude Code trace is what the agent did with it.

### Step 6: Revoke Bob and time it (terminals B and A)

**Do this.** In terminal B, check that Bob's key works.

```bash
./scripts/probe-gateway.sh sk-agw-bob-demo
```

What this does: sends one tiny request with Bob's key. The gateway forwards it to Anthropic, so it uses a few tokens of your key. It changes no files.

Note the time. In your editor, delete Bob's entry from `agentgateway/config.yaml`: the `- key: sk-agw-bob-demo` line and the three `metadata`, `user` and `team` lines under it. Save the file. In terminal A, stop agentgateway with `Ctrl+C`, then start it again:

```bash
agentgateway -f agentgateway/config.yaml
```

What this does: starts agentgateway again with the edited config. `ANTHROPIC_API_KEY` is still set in terminal A. It changes no files.

In terminal B, try Bob's key again.

```bash
./scripts/probe-gateway.sh sk-agw-bob-demo
```

What this does: the same request with Bob's key. It changes no files.

**What you should see.** The first probe prints `HTTP 200: accepted and forwarded to Anthropic.` After the restart it prints `HTTP 401: rejected at the gateway.` The whole change took well under a minute.

**Why.** Containment is one edit at one point, not a hunt for keys on laptops.

### Step 7: Clean up

**Do this.** In terminal A, stop agentgateway with `Ctrl+C`, then remove the key from that terminal.

```bash
unset ANTHROPIC_API_KEY
```

What this does: removes your key from terminal A. It changes no files.

Put Bob back, so the config matches the repository again.

```bash
git checkout -- agentgateway/config.yaml
```

What this does: restores `agentgateway/config.yaml` from the last commit, so Bob's key is back. It changes only that file.

Close terminal B, so the gateway settings go with it. When you have finished with the workshop, stop the LGTM container too:

```bash
./scripts/stop-lgtm.sh
```

What this does: stops and removes the `workshop-lgtm` container and the events in it. It changes no files.

**What you should see.** `Stopped and removed workshop-lgtm.`, and `git status` shows no change to `agentgateway/config.yaml`.

**Why.** Your real key should not outlive the lab, and the lab data has no place on your laptop afterwards.

## You're done when

The step 4 query shows Alice in both `agentgateway` and `claude-code` lines, and after step 6 Bob's key gets 401. Post `Bob blocked` in the chat. On your own, write it in your workbook.

## If it goes wrong

- **`agentgateway: command not found`:** it is not on your PATH. See the pre-work, step 5.
- **`HTTP 401: rejected by Anthropic`:** the gateway forwarded the request, but the backend key in terminal A is wrong or empty. In terminal A, stop agentgateway with `Ctrl+C`, run step 1 again, and paste the key carefully.
- **`HTTP 404` or `HTTP 400` from the probe:** the gateway forwarded the request, but Anthropic did not accept the model name in `scripts/probe-gateway.sh`. Check that your key can use that model.
- **`No answer from http://localhost:4000`:** agentgateway is not running in terminal A, or it failed to start. Read the last lines in terminal A.
- **Alice's prompt fails with an authentication error:** check that you sourced `agentgateway/claude-agentgateway.env.sh` in terminal B. agentgateway reads the key from the `Authorization: Bearer` header, which `ANTHROPIC_AUTH_TOKEN` sets. `ANTHROPIC_API_KEY` sends a different header, and the gateway rejects it.
- **`Extra inputs are not permitted`:** open `agentgateway/claude-agentgateway.env.sh`, remove the `#` in front of the `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` line, save, and source the file again. Fallback: if it still fails, watch the facilitator's screen for steps 3 to 5 (on your own, read each "What you should see" instead) and do step 6 yourself.
- **No `agentgateway` lines in Loki:** set the time range to **Last 1 hour**. If there are still none, look for any line that carries Alice's email, whatever its service:

  ```logql
  {service_name=~".+"} | user_email="alice@example.com"
  ```

You put one gateway in front of every model request. It rejected unknown keys, kept the real key to itself, put a user on every request, and revoked Bob in under a minute. Together with Lab 1 and Lab 2, you can now see what an agent does, catch it when it misbehaves, and cut it off.
